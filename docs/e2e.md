# E2E Testing (Playwright)

Browser-level end-to-end tests live in `frontend/e2e/`, configured by
`frontend/playwright.config.ts` and run in CI by `.github/workflows/e2e.yml`.

## One-time setup

```bash
cd frontend
npm i -D @playwright/test      # installs the pinned version + updates the lockfile
npx playwright install chromium # downloads the browser binary
```

> `npm ci` (and CI) will fail until the lockfile is regenerated by the
> install above — `package-lock.json` is only in sync after running it once.

## Running locally

The suite expects the app reachable at `http://localhost:3000`. Two ways to
get there:

**Full local stack (recommended):**

```bash
docker compose up -d          # backend, Keycloak, postgres, redis (repo root)
cd frontend
npm run test:e2e              # playwright boots `npm run dev` itself via webServer
```

Already have `npm run dev` running? Playwright reuses it
(`reuseExistingServer` outside CI).

**Against a remote environment (staging-URL mode):**

```bash
cd frontend
PLAYWRIGHT_BASE_URL=https://staging.example.com npm run test:e2e
```

When `PLAYWRIGHT_BASE_URL` is set, the local `webServer` is skipped — the
target must already be serving.

Useful flags:

```bash
npm run test:e2e                     # headless run
npm run test:e2e:ui                  # Playwright UI mode (watch/debug)
npm run test:e2e -- smoke.spec.ts    # single file
npm run test:e2e -- --headed         # watch the browser
npm run test:e2e:report              # open the last HTML report
```

## What runs without credentials

`e2e/smoke.spec.ts` covers only public routes — `/` (landing), `/login`,
`/signup` — and needs no test account. The `/login` and `/signup` tests
assert the browser *requests* the Keycloak endpoint, so they pass even if
Keycloak is down; when it answers, they also check the hosted login form.

## Authenticated tests

`e2e/auth.setup.ts` performs one real Keycloak login and saves the session
to `e2e/.auth/user.json` (gitignored). Specs like
`e2e/appointments.spec.ts` reuse it via `test.use({ storageState })`.

Both are **skipped by default** and only run when credentials exist:

```bash
E2E_TEST_EMAIL=patient@example.com \
E2E_TEST_PASSWORD=secret \
npm run test:e2e
```

The test user must already exist in the Keycloak realm the app points at
(`NEXT_PUBLIC_KEYCLOAK_*`). `appointments.spec.ts` assumes a **patient**
account — adjust the target route for doctor/admin accounts.

## Environment variables

| Variable | Purpose | Where set |
|---|---|---|
| `PLAYWRIGHT_BASE_URL` | Target URL; skips local `webServer` when set | shell / `vars.E2E_BASE_URL` in CI |
| `E2E_TEST_EMAIL` | Test user email — enables auth.setup + authenticated specs | shell / `secrets.E2E_TEST_EMAIL` |
| `E2E_TEST_PASSWORD` | Test user password | shell / `secrets.E2E_TEST_PASSWORD` |
| `CI` | Set automatically in GitHub Actions: retries=2, workers=1, no server reuse | — |

## Adding tests

1. Create `e2e/<feature>.spec.ts` — it runs in the `chromium` project
   automatically (`*.setup.ts` files run in the `setup` project instead).
2. Prefer `getByRole` / `getByLabel` / `getByText` selectors; add
   `data-testid` to components rather than coupling to Tailwind classes.
3. For authenticated specs, copy the pattern from `appointments.spec.ts`:
   file-level `test.skip(...)` on the env vars plus
   `test.use({ storageState: authFile })`.
4. Keep public and authenticated coverage in separate files — the
   `chromium` project has **no** global storage state, so anything without
   `test.use({ storageState })` runs logged out.
5. Jest ignores `e2e/` (`testPathIgnorePatterns` in `jest.config.js`) —
   unit-test discovery is unaffected.

## CI behavior (`.github/workflows/e2e.yml`)

- Triggers: every PR, nightly (`17 2 * * *`), and `workflow_dispatch`.
- Steps: checkout → setup-node 20 → `npm ci` →
  `npx playwright install --with-deps chromium` → `npx playwright test` →
  upload `frontend/playwright-report/` as an artifact (always, 14 days).
- **Default mode is staging-URL**: the job reads `vars.E2E_BASE_URL`. A
  docker-compose step is included but commented out — the base compose file
  has no test profile and builds four custom images, too heavy for per-PR
  runs. To enable it, uncomment the step in the workflow and leave
  `E2E_BASE_URL` unset.
- Set the `E2E_TEST_EMAIL`/`E2E_TEST_PASSWORD` repo secrets to light up the
  authenticated specs; without them they skip cleanly.
